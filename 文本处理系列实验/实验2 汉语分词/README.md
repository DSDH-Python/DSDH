# 中国非物质文化遗产文本自动分词系统实验操作说明书

## 1. 实验概述

本实验使用项目提供的 CRF（条件随机场）模型，对非物质文化遗产中文文本进行字符级序列标注和自动分词，并对分词结果进行词长、词频和词云分析。

实验主流程为：

> 选择语料文件夹 → 数据处理 → CRF 自动分词 → 数据分析

程序按行读取 UTF-8 文本，将每个非空行作为一个处理单元，去除部分空白字符后拆成单字，交由 CRF 模型预测词边界。程序提供的样例语料包括《孟姜女传说》《河西宝卷》和《蒙古族长调民歌》，位于 [data](./data/) 目录。

## 3. 运行方式与环境准备

### 3.1 使用已打包程序（推荐）

1. 将 `dist(打包完成的)\ICHAutoWordSegGUI` 文件夹整体保留或复制到一个本地目录。
2. 进入该文件夹，双击 `ICHAutoWordSegGUI.exe`。
3. 不要只复制或移动 EXE 文件。程序还依赖同目录的 DLL、`crf` 模型和执行文件、`Fonts` 字体、停用词表等资源。
4. 如果通过快捷方式启动，请将快捷方式的“起始位置”设置为 `ICHAutoWordSegGUI.exe` 所在目录。程序读写 `test.txt`、`output.txt` 和图表时使用当前工作目录中的相对路径。

### 3.2 从 Python 源码运行

项目环境清单指定 Python 3.8.10，并固定了 PyQt5、Matplotlib、WordCloud 等依赖。清单末尾的 `prefix` 指向原开发机的 `F:\Anaconda\envs\pyqt5_py38`，在其他计算机上使用前，应先复制 `environment.yml` 并删除或改写该机器专属的 `prefix` 行，再在 Anaconda Prompt 中创建环境：

```text
conda env create -f environment.yml
conda activate pyqt5_py38
cd /d "C:\Users\<用户名>\Desktop\实验2：非物质文化遗产自动分词系统"
python ICHAutoWordSegGUI.py
```

请将路径中的 `<用户名>` 替换为本机用户名。启动前确认当前目录是项目根目录；否则程序可能找不到 `crf`、字体或停用词等相对路径资源。项目清单中的依赖版本较旧，若环境创建失败，先检查 Python/Conda 版本、网络或镜像配置，不要随意升级单个核心依赖后将结果与原环境视作完全等价。

## 4. 输入语料准备

1. 在本机新建一个专用于本次实验的语料文件夹。
2. 将待处理语料保存为 UTF-8 编码的 `.txt` 文件。目录可以包含多个文本文件；程序会递归读取所选目录下的文件。
3. 为避免误读，所选目录及其子目录中只放本次需要处理的 UTF-8 文本文件，不要放图片、Word 文档、程序文件或其他非文本文件。当前实现没有按扩展名筛选文件。
4. 保留正常的中文段落和换行。程序以原文件的每个非空行作为一个处理单元；同一段若被硬换行拆成多行，会被当成多个单元。
5. 不要在一次实验中反复选择不同语料文件夹。程序当前不会在重新选择目录时清空已读入的文本，也不会在重复预处理时清空已有缓存。需要换一批语料时，关闭并重新启动程序，再选择新的文件夹。

项目自带的 [data](./data/) 文件夹可用作入门样例。首次练习时可将该目录作为输入目录；若直接选择它，确认其中只有本次要处理的文本。

## 5. 详细实验步骤

### 步骤一：启动并载入语料

1. 按第 3 节选择一种方式启动程序。
2. 主窗口标题为“中国非物质文化遗产文本自动分词系统”，包含路径输入框、信息提示区域，以及“数据处理”“自动分词”“数据分析”按钮。
3. 点击“浏览”，在目录选择框中选中语料文件夹并确认。
4. 路径框显示所选目录；信息提示区域显示“语料库样例”及最多前 30 个非空文本行，供检查是否读入了预期内容。
5. 如果预览为空，先检查是否选中了正确的目录，以及目录中是否包含可按 UTF-8 读取的文本文件。

### 步骤二：数据处理

1. 点击“数据处理”。
2. 程序逐行清理已载入文本：移除全角空格、制表符、普通空格，并去除行首尾空白；清理后为空的行会跳过。
3. 每个保留行按 Unicode 字符拆分为单字序列。程序不会执行繁简转换、标点清洗、人工校对或句子切分。
4. 信息提示区域展示前 5 个处理单元的字符级格式。
5. 项目根目录下生成/覆盖 `test.txt`。其格式为每个字符占一行，句子或处理单元之间以空行分隔，例如：

```text
孟
姜
女

传
说
```

分词步骤使用此文件作为 CRF 输入。确认 `test.txt` 已更新且内容来自本次语料，再继续实验。

### 步骤三：自动分词

1. 点击主窗口“自动分词”，打开自动分词窗口。左侧“原始文本”区域显示已读入的原始文本。
2. 点击“开始分词”。
3. 程序调用 `crf` 目录中的 CRF++ 测试程序及随项目提供的 `model`，对 `test.txt` 中的字符序列预测标签，并将 CRF 原始结果写入项目根目录的 `output.txt`。
4. 右侧“分词后文本”区域以 `/` 标记词边界。例如 `非/物质/文化/遗产/` 表示四个词。窗口中的结果按处理单元换行显示。
5. 可打开 `output.txt` 检查底层结果。每行通常由字符、制表符和标签组成，例如 `申<TAB>B-tag`。程序根据标签中的 `B/M/E/S` 前缀恢复词边界；`B/M` 表示继续累积当前词，`E/S` 表示词结束。
6. 同一窗口内点击多次“开始分词”会重新生成分词结果并覆盖 `output.txt`。如需保留每次结果，请在下一次运行前复制并重命名输出文件。

### 步骤四：数据分析

1. 完成至少一次成功的自动分词后，关闭或保留自动分词窗口均可，回到主窗口并点击“数据分析”。
2. 分析窗口提供以下按钮：

| 按钮 | 统计口径与显示内容 | 生成文件 |
|---|---|---|
| 词长统计 | 先排除停用词，再统计词长；图中展示按词长升序排列的前 10 个不同词长及其词数 | `plot.png` |
| 词频统计 | 排除停用词后统计词频，图中展示词频最高的前 10 个词 | `bar.png` |
| 词云展示 | 排除停用词后按词频生成词云，最多展示 1000 个词 | `wordcloud.png` |

3. 点击任一按钮后，图像显示在窗口右侧，并保存到程序工作目录。
4. 更换了语料后，必须重新执行“数据处理”和“自动分词”，再查看分析。分析数据来自最近一次成功生成的分词词表；未运行分词或没有有效词条时，统计结果可能为空或无法生成图像。
5. 图片文件会被同名结果覆盖，需保留多个版本时请及时复制备份。

## 6. 结果文件与实验记录

建议每次实验建立独立结果目录，并记录以下信息：

| 记录项 | 建议内容 |
|---|---|
| 实验日期与操作者 | 日期、姓名或编号 |
| 运行方式 | 打包版 EXE 或 Python 源码 |
| 输入语料 | 文件夹、文本文件名、文本来源及编码 |
| 语料规模 | 文件数、行数或字符数；可在实验记录中自行统计 |
| 数据处理 | 是否生成 `test.txt`，是否发现空行、异常字符或意外换行 |
| 分词模型 | 项目随附的 `crf/model` |
| 分词结果 | 保存的 `output.txt`、界面结果截图及人工抽查样例 |
| 分析结果 | `plot.png`、`bar.png`、`wordcloud.png` |
| 观察与误差 | 领域词、人名、地名、专名、标点附近边界等错误案例 |

本项目没有在主界面中提供准确率计算或人工标注对照功能。因此若实验要求报告 Precision、Recall、F1 等指标，应另行准备人工标注的标准答案并使用独立评测流程；不要把词频统计或图表当作分词准确率。

## 7. 模型训练相关说明

主程序当前可执行的标准流程使用已有 CRF 模型进行**推理**，不是训练。虽然项目包含 [TrainWindow.ui](./TrainWindow.ui) 与 [TrainWindow.py](./TrainWindow.py)，其界面列出 CRF、Bi-LSTM-CRF、BERT、RoBERTa、ALBERT 选项，但主程序没有导入、实例化或连接该训练窗口，不能从当前主界面启动这些模型训练。`logs` 中的文件是历史运行日志，不会由当前 GUI 自动读取或展示。

[crf/指令.txt](./crf/指令.txt) 记录了单独使用 CRF++ 的训练、推理及评测命令示例：

```text
crf_learn template train.txt model
crf_test -m model test.txt > output.txt
```

第一条命令需要事先准备符合 CRF++ 格式并带有人工标签的 `train.txt`；本项目当前没有提供该训练文件。指令中的 `conlleval.pl` 评测脚本也未随项目提供。训练会生成/覆盖模型文件，执行前应备份 `crf/model`。因此初次使用者应按本说明书完成现有模型的分词实验，不要将训练界面的选项当作已接通的实验步骤。

## 8. 常见问题排查

| 现象 | 检查与处理 |
|---|---|
| 点击“浏览”后预览为空 | 选中的是目录而非文件；确认目录内有文本文件，并确认文本为 UTF-8 编码。 |
| 读取时出现编码错误或乱码 | 将输入文本另存为 UTF-8，再重新启动程序并重新选择目录。 |
| 点击“数据处理”后 `test.txt` 空白或没有更新 | 确认先载入了正确语料；检查文本是否只有空白内容；确认程序对工作目录有写入权限。 |
| 点击“开始分词”后没有结果、结果未变化或 `output.txt` 未更新 | 确认已成功执行数据处理；从项目根目录启动源码版，或从完整打包目录启动 EXE；检查 `crf` 中是否保留 `crf_test.exe`、`model` 和相关 DLL。程序没有对外部命令失败进行友好的界面提示，必要时查看命令行输出。 |
| 自动分词结果看似混合了旧文本 | 重新启动程序，只载入本次实验的语料目录，然后依次重新执行数据处理和自动分词。 |
| 数据分析为空或没有图表 | 先成功运行自动分词；确认停用词过滤后仍有词条；确认工作目录可写，并保留 `Fonts\simhei.ttf`。 |
| 中文图表显示为方框 | 确认 `Fonts\simhei.ttf` 存在于程序目录的 `Fonts` 子目录，不要单独移动该字体文件。 |
| 换了输入文件夹但结果仍包含前一批语料 | 当前实现会累积已载入文本；关闭并重启程序后再选择新目录。 |
| 程序启动失败 | 源码版检查 Python 3.8 环境及依赖是否安装；打包版检查是否复制了完整目录，而不是只复制 EXE。 |
