1.1　数字人文的基本概念

定义。 数字人文（Digital Humanities, DH）是计算机科学与人文科学交叉融合形成的研究领域，它运用数字技术进行人文资料的获取、清洗、分析、可视化与阐释，并反过来反思技术本身对人文知识生产方式的影响。它既是一套方法工具集，也是一种研究姿态。

辨析三组常见误解：

  • 数字人文 ≠ 把书扫描成 PDF。扫描只是数字化（digitization），数字人文追求的是可计算（computable）与可提问（queryable）。
  • 数字人文 ≠ 用 Word 写论文。写作载体变化不等于研究范式变化。
  • 数字人文 ≠ 纯技术开发。没有人文问题的技术炫技，只是"数字"而非"数字人文"。

核心张力（本教材的立身之本）。 算法逻辑追求确定性，数据假设隐含立场，人文解释强调语境与多元——三者之间的张力，正是"教学即研究"理念的来源。本教材所有实验都要求学生记录假设、暴露偏差、给出解释，而非只输出一张漂亮图表。

1.2　发展历程：从穿孔卡片到大模型

  • 奠基期（1949–1990）：1949 年 Roberto Busa 神父用穿孔卡片为《托马斯·阿奎那全集》编制语词索引，被视为人文计算的起点。
  • 术语期（1990s–2004）："人文计算"（Humanities Computing）成为学科称谓；TEI（文本编码倡议）、XML 等标准成熟。
  • 普及期（2004–2010）：2004 年 UCLA 研讨会后"数字人文"一词被广泛采用；数字人文中心（DH Center）在欧美高校批量出现。
  • 融合期（2010–2020）：开放数据、众包、GIS、社会网络分析进入主流；DH Awards（2012 起）成为社区风向标。
  • 智能期（2020–至今）：大语言模型、生成式 AI、多模态模型重塑研究路径，也带来"AI 替代人文思考"的伦理争论。

国内脉络：从 CADAL、中国基本古籍库等数据库建设，到武汉大学、中国人民大学、南京大学等高校数字人文中心成立，再到"数字人文"成为图书情报与档案管理一级学科的重要交叉方向。苏州大学社会学院"数据科学与数字人文导论"课程即本教材的实践土壤。

1.3.1　批判与担当：数字人文的伦理坐标（知识库延展）

数字人文从来不只是"方法"，它同时是一种立场。两篇知识库文献可作为本教材伦理讨论的锚点：

  • 《有担当的数字人文》（译介 Gold & Klein, "A DH That Matters"）：主张数字人文应直面公共议题与社会不公，警惕把技术当作中立工具。文中引述 Noble《压迫的算法》（Algorithms of Oppression）与 Hicks《编程的不平等》（Programmed Inequality），指出算法偏见与性别/种族排斥并非偶然 Bug，而是被编码进系统的结构性问题。
  • 《批判性再谈"数字人文"》（许喆，《数字人文研究》2026）：强调应将数字人文理解为方法论而非独立学科，批判"技术中心主义"教育，提倡"问题中心 + 批判思维"，并援引 FAIR 原则（可发现、可访问、可互操作、可复用）作为基础设施建设的底线。文章把学界态度归纳为三类——否定者、狂热拥护者、批判性接受者——本教材鼓励第三种。

课堂讨论：找一篇你所在专业用"算法"做的研究，判断它更接近"技术中心主义"还是"问题中心 + 批判思维"？它是否披露了数据来源与偏见？

1.4　人文数据的特点与获取方式

人文数据的五个特点：

  1. 非结构化为主：手稿、图像、口述录音难以直接入表。
  2. 多模态并存：同一研究对象可能同时有文本、图像、地理、音频。
  3. 强语境依赖：一句话脱离年代、作者、版本便可能误读。
  4. 版权与伦理复杂：家谱、书信、方言录音涉及隐私与权属。
  5. 长尾分布：绝大多数素材低频、分散，难以规模获取。

2.1　为什么文本分析是数字人文的"母方法"

人文研究的对象绝大多数以文本形式存在——诗文、方志、书信、报刊、档案。把文本转化为可计算对象，是几乎所有 DH 研究的第一步。但要牢记本教材的核心张力：任何一次"清洗"都是一次解释。删掉"之乎者也"提高了统计效率，却也可能删掉了文体研究的关键证据。

2.4.1　进阶：从 LDA 到 BERTopic 与嵌入模型（知识库延展）

LDA 假设"词袋"（bag-of-words），丢失了词序与语义。近年主题建模迅速向上下文嵌入演进：

  • BERTopic（Grootendorst, 2022）：用 Sentence-BERT 把文档编码为句向量，再做聚类（如 HDBSCAN）+ 类内 c-TF-IDF 提取主题词。知识库中佛教文本研究已用 GuwenBERT 做古文 BERTopic，对经疏做主题归纳。
  • TopicGPT（Pham et al., 2024, NAACL）：用大语言模型直接生成并 refine 主题标签，降低人工读主题词的成本。
  • Gibbs-BERTopic：把 LDA 的 Gibbs 采样与 BERT 嵌入结合的混合路线。

认识局限：词袋模型无法区分"兵"（兵器/士兵/军事）在不同语境的含义；嵌入模型虽能捕捉语义，却把"意义"交给黑箱。知识库文献反复提醒——技术是透镜，意义的发现始终属于人。

2.4.2　思想史案例：当主题建模遇见《鲁滨逊漂流记》（知识库延展）

惠海峰（Hui）在 Digital Scholarship in the Humanities（2025）提出 LDA + Word2Vec 三维可视化混合模型，对《鲁滨逊漂流记》做主题—语义联合分析：

  • 用 LDA 抽出 5 个主题，再用 Word2Vec 把主题词映射为向量，在三维空间观察主题间的语义距离；
  • 发现 "thought"（思想）一词贯穿几乎所有主题，印证小说作为"精神自传"的特质；
  • 用儿童改编版验证主题稳定性，并跨作品比较《摩尔·弗兰德斯》《辛格尔顿船长》，展示"主题 + 词向量"如何支撑文学思想史的可计算研究。

实验延伸：取你熟悉的任一长篇，先跑 LDA 取主题词，再用 Word2Vec（或教材预部署句向量）把主题词投影到二维/三维，观察哪些主题在语义上"靠近"——这比单纯读主题词表更接近"概念地图"。

2.8　案例拓展：植物意象的 LDA 与濒危文字的智能识别（知识库延展）

(1) 植物意象主题建模（马开颜等，《数字人文研究》2022） 研究以 34 种常见树木、17,889 条现当代文学词条为对象，用 jieba 分词后构建 LDA 主题模型，训练出 7 个主题，并用 Gephi 绘制"植物—主题""植物—词语"二部网络图，使植物意象与文学场景的关联"显性化"。7 个主题被命名为：细腻情绪、生活场景、抽象思考、视觉感知、听觉感知、温馨回忆、厚重感怀。

  • 方法要点：主题数靠"困惑度 + 解释性"平衡确定；高频但无文化内涵的词（如"枝叶""树梢"）需预先剔除，避免"中心主题湮没"；二部网络图把传统的"选择性呈现"转为"全景性呈现"。

(2) 水书文字数据库与智能识别平台（孙治弘等，《数字人文研究》2026） 水书是水族独有文字，因手写繁复、传承人稀缺而濒临消失。研究构建"书—篇—句—字"四级文字数据库，并提供智能识别平台：

  • 采用 DBNet（文本检测）+ CRNN（文本识别）两阶段深度学习模型；
  • 引入 Unicode 私有区编码方案，为水书字符建立标准字符集；
  • 针对低资源、长尾分布、复杂版式做数据增强优化，识别效果显著优于通用 OCR。

模块贯通：植物意象研究是"主题建模 + 可视化"（模块二→模块三）的完整范例；水书平台则是"OCR + 数据库 + 濒危文字保护"（模块二→模块五）的前沿个案，二者共同说明——数字人文既能处理"海量文本的规律"，也能抢救"极少数人的记忆"。

学生真实操作案例：用爬虫构建 DHQ 论文语料库（模块二·数据采集）

案例来源：课程实验报告《20241031+1128+1205+1212 实验报告》（社会学院《数据科学与数字人文导论》）。原报告以 prompt 驱动方式，让学生用 BeautifulSoup 爬取 Digital Humanities Quarterly（DHQ）网站各卷期的文章与 PDF 链接，作为后续文本分析的语料。

真实操作步骤（学生原意整理）：

  1. 获取目标卷期页 http://www.digitalhumanities.org/dhq/vol/18/3/index.html 中所有刊期/文章的链接；
  2. 在指定文章页中，提取 class="articleInfo" 的 <div> 下的 <a> 链接，得到该卷期全部文章；
  3. 进入每篇文章页，提取 .pdf 结尾的下载链接（如 https://dhq-static.digitalhumanities.org/pdf/000678.pdf）。

可复现代码（基于学生 prompt 整理）：

# 目标：爬取 DHQ 某一卷期下的所有文章 PDF 链接
import requests
from bs4 import BeautifulSoup

vol_url = "http://www.digitalhumanities.org/dhq/vol/18/3/index.html"
soup = BeautifulSoup(requests.get(vol_url, timeout=20).text, "html.parser")

# 步骤2：提取 class="articleInfo" 的 div 下的文章链接
article_links = []
for div in soup.find_all("div", class_="articleInfo"):
    a = div.find("a", href=True)
    if a:
        article_links.append(a["href"])
print(f"共发现 {len(article_links)} 篇文章")

# 步骤3：进入每篇文章页，提取 PDF 下载链接
pdf_links = []
for link in article_links:
    psoup = BeautifulSoup(requests.get(link, timeout=20).text, "html.parser")
    for a in psoup.find_all("a", href=True):
        if a["href"].endswith(".pdf"):
            pdf_links.append(a["href"])
print(pdf_links)

2.10 大语言模型辅助文本分析：从 distant reading 到 RAG 知识库（V2.0）

for w in oa["results"]:
    print("OA", w["publication_year"], w["title"], "->", (w.get("primary_location") or {}).get("source", {}).get("display_name"))

3.1　视觉修辞：图表是有立场的

数据可视化是一种"视觉修辞"。同一份数据，选择不同的坐标起点、配色、聚合粒度，会引导出完全不同的结论。人文导向的可视化，强调让读者看见复杂性与不确定性，而非制造虚假的确定感。

三条人文可视化原则：

  1. 诚实优先于美观——不用截断坐标轴放大差异。
  2. 保留不确定性——用误差带、模糊边界表达数据的残缺。
  3. 提供语境——每张图都附数据来源、时间范围、处理方法。

3.1.1　延展：约翰娜·德鲁克的"capta"批判（知识库延展）

约翰娜·德鲁克（Johanna Drucker）在《Graphical Approaches to the Digital Humanities》中指出：我们习以为常的"数据"（data）一词暗含"已被给定"之意，但人文研究中绝大多数对象并非天然是数据，而是被建构为数据的——她造词 capta（"被捕捉/被建构之物"）以强调这一点。

她批判标准化可视化（条形图、网络图、GIS）自带一套认识论偏见：把不确定的、主体性的、含混的人文经验，强行压进精确坐标与清晰边界。人文图形体系应当容纳模糊性与主体性，而非假装客观。这与本模块 3.1 的"诚实优先于美观"原则互为表里——可视化首先要诚实于"数据是被人建构的"这一事实。

3.8　延展：人文数据标注与历史可视化的知识生产（知识库延展）

可视化之前，往往需要先"造数据"。北京大学可视化暑期学校（2026）张宇研究员的《人文数据标注》讲座给出一套可操作的方法论：

  • 四种科学范式（Jim Gray, 1998 图灵奖）：经验→理论→计算→数据范式。人文学科正悄然进入数据范式——以 CBDB（中国历代人物传记资料库，19 万+人物）为例，"唐代有哪些文人"已从遍查典籍变为一次检索。
  • 高效标注：① 基于大语言模型的预标注——把标注规范、标签体系、编码手册组织成结构化提示词，让 LLM 粗加工，人工转为"审核纠错"；并以 RAG 标注记忆库让质量随反馈迭代；② 主动学习（Active Learning）——优先挑模型"最拿不准"的样本标注，用最少标注量逼近全量效果。
  • 低成本标注：众包（如 Amazon Mechanical Turk）、游戏化（ESP Game 吸引 20 万玩家标注图片；Borderlands Science 嵌入《无主之地3》吸引 400 万玩家做微生物系统发生学标注）。
  • 应对主观性：质性编码三步法（开放编码→主轴编码→选择性编码，扎根理论），例如把"政权合法性叙事"归并为"祖先合法性 = 天命 + 世代功绩 + 帝王认可"。
  • 案例 OldVisOnline：汇集 1.3 万张 1950 年前"前计算机时代"可视化图像 + 17.9 万张中国古籍插图及元数据，开发 VisTaxa 编码工具，构建含 51 个分类单元的可视化设计分类树——第一次系统回答"历史上的可视化用过哪些设计手法"。

与模块衔接：数据标注是模块二（NER、句读、实体关系）的"上游劳动"，也是模块三可视化的"原料车间"。当你画一张地图或桑基图前，不妨先问：这些数据是谁、依什么规范标注的？

q = 'document image analysis cultural heritage computational art history'
# 1) OpenAlex：开放学术图谱（聚合期刊/会议/预印本，含被引数）
url_oa = "https://api.openalex.org/works?search=" + urllib.parse.quote(q) + "&per_page=10&sort=cited_by_count:desc"
oa = json.loads(urllib.request.urlopen(url_oa, timeout=30).read())
for w in oa["results"]:
    print("OA", w["publication_year"], w["title"], "->", (w.get("primary_location") or {}).get("source", {}).get("display_name"))
# 2) CrossRef：期刊 DOI 元数据（代表期刊网站 / 电子期刊，可溯到出版社原文）
url_cr = "https://api.crossref.org/works?query=" + urllib.parse.quote(q) + "&rows=10"
cr = json.loads(urllib.request.urlopen(url_cr, timeout=30).read())
for it in cr["message"]["items"]:
    print("CR", (it.get("issued",{}).get("date-parts",[[""]])[0][0]), (it.get("title") or [""])[0])

6.1　把关系变成结构

6.2　网络基本属性

概念含义人文解读
度（Degree）一个节点连了几条边交游广度

6.3　标志性实验一：文人交游网络（NetworkX + Gephi）

import networkx as nx

# 读取明清文人交游数据（边表：人物A, 人物B, 交往强度）

# 计算中心性

print("中介中心性最高：", max(bc, key=bc.get))
print("度中心性最高：", max(dc, key=dc.get))

# 导出到 Gephi 做可视化

6.9　案例拓展：诗词意象的"知识图谱"挖掘——以《鹧鸪》为例（知识库延展）

来源：李妍斐《利用"知识图谱"网站诗词库 API 及文本挖掘技术分析诗词意象的方法——以挖掘"鹧鸪"意象隐藏模式为例》（四川大学文学与新闻学院，《数字人文》2024 年第 2 期）。论文代码已开源：GitHub LiYanfei95/analyzing_poetic_imagery。

如果说 6.3–6.5 的网络是"人与人"的关系结构，那么诗词意象的知识图谱就是"词与词、意与意"的语义网络——它是文化计算的另一种形态，也是"集唐诗"研究可直接迁移的范式。

可复用的四步方法链：

  1. 取数：调用"知识图谱"网站（cnkgraph.com）开放的诗词库 Web API，获取含特定意象的结构化诗句，免去爬虫的合规风险；
  2. 句嵌入聚类：用 SikuBERT（在《四库全书》语料上继续预训练的古文语言模型）载入 SBERT 计算句向量，再用 DBSCAN 密度聚类，发现意象使用的类别模式；
  3. 关联规则：用 BERT-Base-Chinese-WS 分词，跑 Apriori 算法发掘"前提 → 结论"的用词规律；
  4. 人文回环：以算法线索重回文献考证，完成"机器发现—人文学者释义"的闭环。

  • 句子层聚出四类：湘妃典故、游子思妇愁绪、乐府《山鹧鸪》曲、江南客——其中"湘妃类"长期被文学研究者忽略；

  1. 设定 3 个意见领袖 agent 与 20 个普通成员 agent；

  4. 讨论与晚明党社之争记载是否吻合，写"仿真假设的史料依据与边界"。

for w in oa["results"]:
    print("OA", w["publication_year"], w["title"], "->", (w.get("primary_location") or {}).get("source", {}).get("display_name"))
# 2) CrossRef：期刊 DOI 元数据（代表期刊网站 / 电子期刊，可溯到出版社原文）
url_cr = "https://api.crossref.org/works?query=" + urllib.parse.quote(q) + "&rows=10"
cr = json.loads(urllib.request.urlopen(url_cr, timeout=30).read())
for it in cr["message"]["items"]:
    print("CR", (it.get("issued",{}).get("date-parts",[[""]])[0][0]), (it.get("title") or [""])[0])

课堂复现（检索即方法）：下列代码展示如何直接调用 OpenAlex 与 CrossRef 的免费 API 复现本模块文献检索，强调"可溯源"的研究习惯（无需任何密钥）。

# 复现本节课的文献检索（均为免费开放 API，无需密钥）
import urllib.request, urllib.parse, json
q = 'multi-agent digital humanities project workflow'
# 1) OpenAlex：开放学术图谱（聚合期刊/会议/预印本，含被引数）
url_oa = "https://api.openalex.org/works?search=" + urllib.parse.quote(q) + "&per_page=10&sort=cited_by_count:desc"
oa = json.loads(urllib.request.urlopen(url_oa, timeout=30).read())
for w in oa["results"]:
    print("OA", w["publication_year"], w["title"], "->", (w.get("primary_location") or {}).get("source", {}).get("display_name"))
# 2) CrossRef：期刊 DOI 元数据（代表期刊网站 / 电子期刊，可溯到出版社原文）
url_cr = "https://api.crossref.org/works?query=" + urllib.parse.quote(q) + "&rows=10"
cr = json.loads(urllib.request.urlopen(url_cr, timeout=30).read())
for it in cr["message"]["items"]:
    print("CR", (it.get("issued",{}).get("date-parts",[[""]])[0][0]), (it.get("title") or [""])[0])

模块八　人工智能前沿与数字人文实验

8.1 引言：AI 三年跃迁与数字人文的新机遇

2023 年以来，人工智能经历了从"能对话"到"能思考、能行动、能生成"的范式跃迁。大语言模型（LLM）在参数规模与多模态能力上快速演进；2024–2025 年，推理模型让机器展现出类人的逐步推理，AI 智能体（Agent）开始自主调用工具完成多步任务，多模态生成在图像与视频上取得"质变"。对数字人文而言，这意味着史料处理、文化遗产解码、知识组织与叙事表达都获得了前所未有的新工具。本模块梳理近三年最值得数字人文研究者关注的技术进展，并结合真实案例说明其落地点与边界。

8.2 大模型与推理模型：从对话到思考

  • 主流基座：GPT-4o、Claude 3.5、Gemini、Llama 3、DeepSeek-V3 等将文本、图像、语音统一为多模态能力。
  • 推理模型突破：OpenAI 于 2024 年 9 月发布 o1、12 月升级 o3，在数學、编程、博士级科学问答上超越部分人类专家；Google 同步推出 Gemini 2.0 Flash Thinking。
  • 中国突破：DeepSeek-R1（2025-01 发布，2025-09 登《自然》封面）以纯强化学习（GRPO）激发推理能力，无需人工标注思维链；HuggingFace 下载超 1090 万次，训练成本约 29.4 万美元，被《自然》评价为"大模型研究领域的制度破局"，也是首个通过独立同行评审的主流 LLM。
