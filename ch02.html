第 2 章　模块二　人文数据的类型与获取

学习目标：完成本模块后，你应能（1）区分人文数据的五种主要类型与三种结构化程度；（2）说出至少三个可公开获取的开放人文数据门户/仓储，并解释"原生数字"与"数字化副本"的差异；（3）用"来源谱系 + 许可 + 敏感度"三步法评估一份数据的可取用性；（4）独立完成第一次合规数据获取——从一个开放门户取回一份真实数据集，并完成一张数据审计表。

第二部分　课程内容

理论

2.0 思政导入

数据要素：数据已成为与土地、资本并列的生产要素，也是国家竞争力与安全的组成部分。获取人文数据时，既要善用开放资源，也要守住数据主权与个人尊严的边界——不抓取受保护的敏感数据，不将国家与文化数据置于无防护的风险中。自主、合规、负责任地取数，是新时代研究者应有的家国担当。

数据边界：可参照《数据库系统原理》（北京交通大学）课程思政的“家国情怀”导向，与人工智能伦理研究中“数据隐私保护”（韩燕霞，基于联合国教科文组织等 5 个国际文件比较）的素养维度——取数须守住国家与个人的数据边界。

理论

2.1 人文数据长什么样：从"文献"到"数据"

人文学者的直觉材料，往往是"文献"或"实物"：一本地方志、一卷碑拓、一封书信、一张老地图。但一旦进入计算，第一件事不是"分析"，而是把它想清楚能被机器读成什么。

<img width="854" height="600" alt="局部截取_20260923_165449" src="https://github.com/user-attachments/assets/d49af209-dcac-4f32-820e-faaf992c249f" />

同一个对象，常常有多种"数据化身"：

  • 一部地方志 → 扫描图（图像）→ OCR 文本（文本）→ 职官/户口条目表（结构化表格）→ 官员任职网络（关系）；
  • 一张地契 → 高清照片（图像）→ 田亩四至文本（文本）→ 经纬度与边界（时空）。

关键认知：数据的"类型"不是材料的天然属性，而是你为它选择的"问法"。先定问题，再定类型，最后才定工具——顺序反了，就成了拿锤子找钉子。

理论

2.2 五种类型：文本 / 图像 / 时空 / 关系 / 结构化表格

为方便检索与建模，我们把人文数据归为五类，每一类对应一组典型问题：

<img width="1412" height="953" alt="局部截取_20260923_165548" src="https://github.com/user-attachments/assets/2598c7fb-78c3-43f5-8524-085f4d91646a" />

  • 文本类：古籍、报刊、口述转录、书信、剧本、法律条文。典型问题：分词与句读、命名实体识别（NER）、主题模型、风格与情感分析。
  • 图像类：碑帖、画作、器物、老照片、地图、壁画。典型问题：图像识别与检索、破损修复、风格聚类、以图搜图。
  • 时空类：地契、驿道、人物生平地点、事件发生地、城市肌理。典型问题：GIS 叠加、密度与扩散、历史地理重建。
  • 关系类：家谱、师承、交游、社交、引文。典型问题：网络中心性、社群发现、关键节点识别。
  • 结构化表格类：方志条目、藏品编目、统计年报、户籍册。典型问题：聚合、回归、可视化与异常检测。

现实提醒：真实的人文项目大多是多模态的——一份近代报刊既是文本，也是图像，还带着出版地与时间的时空属性。分类是为了上手，不是为了让材料就范。

理论

2.3 结构化程度：结构化 / 半结构化 / 非结构化

除了"类型"，数据还有"规整度"之分，它直接决定清洗成本：

  • 结构化：行列表格（CSV、数据库表），列名固定、取值规范，pandas 可直读直算。
  • 半结构化：有标签但不严整（TEI/XML、JSON、HTML），需先解析再抽取。
  • 非结构化：纯文本、图像、音频、视频，机器读不懂"意思"，需先抽取特征（向量、标签、坐标）才能计算。

一个重要反直觉：最规整的数据，往往不是最有张力的数据。方志里的户口数是结构化的，却回答不了"灾年为啥逃荒"；一封没有字段的书信，反而藏着最真实的历史动机。所以"结构化"是手段，不是目的。

理论

2.4 来源谱系：原生数字、数字化副本与衍生数据

取数据前，先问它"从哪来"。同一份内容，来源不同，可信度与用法天差地别：

  • 原生数字（born-digital）：本来就是数字形态，如网络档案、传感器流、数据库导出。最"原汁"，但仍需核对其采集方法。
  • 数字化副本（digitized surrogate）：纸/实物被扫描或拍摄而成。请牢记它是代理（proxy），不是原物——分辨率、色彩、装帧残缺、扫描偏色，都是副本自带的信息损耗。
  • 衍生数据（derived）：别人跑模型得到的向量、标签、知识图谱。可取用，但必须能追溯到原数据与所用算法，否则就是"黑箱里的黑箱"。

理论

2.5 合规获取：许可、敏感度与一条红线（本模块核心能力）

如果本模块只让你带走一样东西，我们希望是一套合规取数的判断力。请把它当成取数前的随身 checklist：

<img width="2430" height="767" alt="局部截取_20260923_170742" src="https://github.com/user-attachments/assets/efb51419-db54-4770-90e4-f575b6b32652" />

  • 许可分级：CC0（放弃权利）/ CC BY（署名）/ CC BY-NC（非商用）/ CC BY-SA（署名+相同方式）/ 版权所有 / 受限访问。先看许可，再决定用法。
  • 权限状态：open（可直接下）/ restricted（需申请）/ closed（不开放）。closed 不抓取全文，不绕过权限墙。
  • 敏感度：家谱中的在世亲属、口述史受访者、地方信仰的持有者——真实个人与活着的社群，须经授权与同意方可采集、公开。
  • 数据引用：像引文献一样引数据——作者、年份、仓储、DOI、版本号一个都不能少，让他人能复现你的取数。

一条红线：不抓取 closed-access 全文，不绕过任何权限墙；凡涉在世社群或敏感文化事项，先获授权、再谈取用；拿不准时，停下来问，而不是先下数据。

课堂练习2：为一份数据写“数据护照”

  • 目标：给你在 2.6 取回的真实数据，补一份说明它“从哪来、能不能用”的数据卡片。
  • 步骤：
    1. 列出每个字段名与含义（data dictionary）；
    2. 标注每个字段的来源与获取日期；
    3. 用“公开 / 受限 / 敏感”三档标注敏感度；
    4. 写一句合规结论（能否在教学中使用）；
    5. 用表格呈现上述信息。
  • 工具：Markdown 表格或任意表格软件。
  • 产出：一张数据护照表。
  • 评价量规：字段齐全（30%）、敏感度标注合理（40%）、合规结论有据（30%）。

课堂复现（检索即方法）：下列代码直接调用 OpenAlex 免费 API 复现本模块文献检索（无需密钥）。

import urllib.request, urllib.parse, json
q = 'data science digital humanities'
url = 'https://api.openalex.org/works?search=' + urllib.parse.quote(q) + '&per_page=10&sort=cited_by_count:desc'
oa = json.loads(urllib.request.urlopen(url, timeout=30).read())
for w in oa['results']:
    print(w['publication_year'], w['title'], '->', (w.get('primary_location') or {}).get('source', {}).get('display_name'))

误用警示：① arXiv 预印本未经同行评审，引用须标 preprint 并追正式版；② 被引数代表影响力非结论正确；③ 商业库（WoS/Scopus/Elsevier/JSTOR/CNKI）本环境无订阅，需机构账号获取后再并入。

第四部分　本章小结

小结

2.8 本章小结与思考

用一句话收束本模块：人文数据的第一步，不是跑模型，而是认清它是谁、从哪来、能否取用。 请带走三件事——

  • 五种类型 + 三档结构化：文本/图像/时空/关系/表格，结构化/半结构化/非结构化，类型决定能问的问题；
  • 来源谱系三步：原生数字、数字化副本、衍生数据，数字副本是代理不是原物；
  • 合规红线：先看许可与权限，再谈取用；涉在世社群先授权，closed 不抓取、不绕墙。

###思考题

  1. 选一个你熟悉的人文材料，列出它的至少三种"数据化身"，并各写一句"这种化身能回答、另一种回答不了"的问题。
  2. 找一份声称"开放"的数据集，读它的许可条款，判断你在课程作业中能否商用、改编、再分发，依据分别是什么条款？
  3. "数字化副本是代理而非原物"。在你关注的领域，这种代理会丢失哪些关键信息？这些信息丢失会让什么结论变得不可靠？
